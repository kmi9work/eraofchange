# ТЗ № 2. Этап 2 «Функциональность» — отчёт о внедрении

Ветка: `many_teams` (`eraofchange` + `era_front`). Этап 1 (данные) — `TZ-1-otchet-o-vnedrenii.md`,
структура данных — `TZ-1-struktura-dannyh.md`. Контракт фронта — `era_front/docs/many_teams/TZ-2-realizaciya.md`.

Принцип этапа: **отдельного режима «одна команда / много команд» нет**. Приложение всегда работает
в разрезе «текущего государства»; если мастера работают за одну страну, поведение и вид экранов
обязаны совпадать с прежними.

---

## 1. Сквозные изменения

### 1.1. Текущее государство

* Бэкенд: `Country.current` из `session[:country_id]`, `GET /current_country.json`,
  `GET /login_country/:id.json` (несуществующий id → `404`, сессия не меняется).
* Фронт: единый composable `era_front/src/composables/useCurrentCountry.js` — модульное состояние
  (`currentCountry`, `currentCountryId`, `countries`, `reloadToken`) и методы
  `loadCurrentCountry()`, `loadCountries()`, `setCurrentCountry(id)`, `reloadAll()`.
  Смена государства увеличивает `reloadToken`, экраны по нему перечитывают данные **без
  перезагрузки страницы**. Состояние не дублируется в компонентах.
* Шапка: `src/layouts/components/CountryProfile.vue` — название, флаг и выбор государства
  (вставлено в `DefaultLayoutWithVerticalNav.vue` до профиля пользователя); на экране
  «Информация о стране» тот же компонент стоит рядом с заголовком (§ 3.1).
* Навигация: `src/layouts/components/NavItems.vue` — «Дашборд», «Информация о стране»,
  «Политика», «Сражения», «Экономика», «Служебное». Переключателей режима и признаков
  «играбельное государство» нет нигде.

### 1.2. Русь-центричные места на бэкенде

Переведены на текущее государство (подробности — ТЗ № 1, § 9 и приложение А):

* `Region#shown_overall_po`/`show_overall_po(country)`, `PublicOrderItem.add(..., region = nil,
  entity = nil, country = Country.current)` — правка без региона применяется к регионам государства,
  а не к регионам «Руси»;
* `Region#captured_by(who_id, how)` — правка общественного порядка для текущего государства,
  обнуление владельцев поселений — для чужого; если регион присоединяет текущее государство,
  бонус Великому князю начисляется его совету (`RegionsController#captured_by`);
* политические действия: `Country.current.council_players(Job::GRAND_PRINCE)` вместо держателей
  должности «Руси» (`app/models/political_action.rb`);
* доход от вассалов — Казначею текущего государства
  (`engines/vassals_and_robbers/.../concerns/player_extensions.rb`).

### 1.3. Игроки привязаны к государству

`Player#country_id` — основная привязка; `GET /players.json?country_id=&player_type_id=`
(знать — `player_type_id=2`), создание игрока принимает `country_id`. Фильтр «Государство» есть
на экране «Игроки».

### 1.4. Влияние и доход привязаны к игроку

* Влияние всегда ложится на игрока: `PoliticalAction#modify_influence` →
  `InfluenceItem.add(value, comment, player, self)`. Ни один путь начисления влияния не адресует
  должность. Проверяется тестом `test/models/many_teams_tz2_test.rb` — перебор всех типов
  политических действий из справочника с перехватом адресатов влияния.
* Смена держателя должности влияние не переносит: у прежнего игрока оно остаётся, у нового
  начинается с нуля (там же).
* Доход считается по владениям указанного государства: `Player#income_breakdown(country)`
  (+ доход от вассалов отдельной строкой у Казначея), эндпоинт
  `GET /players/:id/income_breakdown.json?country_id=`.

## 2. Раздел «Дашборд» (новый)

* Маршрут `/dashboard` → `src/pages/teams-dashboard.vue`; прежний дашборд переехал в
  `/country` (`src/pages/dashboard.vue` → `src/pages/country.vue`, `git mv`).
* Выбор государств чекбоксами (§ 2.2): отмеченные государства хранятся в localStorage
  (`dashboard_countries`) — это настройка вида, а не игровое состояние; выбор не сбрасывается
  и не требует сохранения на сервер.
* Таблица отношений (§ 2.3): данные — `GET /countries/relations_matrix.json?country_ids=1,5,…`.
  **Строка = пара (A, B)**, где A — отмеченное государство, B — любая другая страна;
  пары между двумя отмеченными не показываются, самопары и дубли отсутствуют. Отдача строки:
  `partner` (A: id, name, short_name, flag_image_name) и `country` (полное представление B
  партиалом `countries/_country`, `relation_partner_id` = A, `relations`, `relation_points`,
  `relation_items`, союзы, эмбарго). Кнопки строки и её правки работают в контексте A.
* Строка таблицы вынесена в общий компонент `src/components/RelationsRow.vue` — «все кнопки,
  как сейчас» не поддерживаются в двух копиях: тот же компонент использует блок «Отношения»
  на экране «Информация о стране» (`src/views/dashboard/Relations.vue`).
* `src/components/AlliancesDialog.vue` получает `partnerCountryId`: союзы считаются для пары
  A ↔ B, а не для жёсткой «Руси» (в режиме одной команды партнёр — «Русь», прежнее поведение).

## 5. «Политика → Политические действия»

`src/views/pages/politics/PoliticalActions.vue`: список должностей —
`/jobs.json?nobles=1&country_id=` (в должности только держатели этого государства и только его
`political_actions`), диалог «Кому?» — знать текущего государства, отметка «выполнено» —
по `(должность, год, государство)`, смена держателя — `PATCH /jobs/:id.json` с обязательным
`country_id`.

Критичное место (§ 5 п. 4): бэкенд формирует новый список держателей как «держатели других
государств + выбранный игрок текущего государства», поэтому смена Великого князя в одном
государстве не стирает совет другого. Покрыто тестами на двух государствах (см. § 10 отчёта).

## 6. «Сражения»

`src/views/pages/politics/Armies.vue`: деление вкладок — по государству, а не по `owner_type`.
Первая вкладка (ключ `own`) — название текущего государства, в ней армии государства и его
знати (`GET /armies.json?foreign=0`), вторая («Зарубеж», ключ `foreign`) — армии остальных
государств (`GET /armies.json?foreign=1`); государство армии приходит полем `country_id`.
Владельцы в форме — только текущее государство и только его знать (`ArmyForm`/`ArmyDialog`),
чужие государства и «незнатные» игроки недоступны. Механики (найм, оплата, перемещение, атака,
разведка) не изменены.

## 7. Движки

* 7.1 Вассалитет: `src/composables/useChecklists.js` грузит
  `/vassals_and_robbers/checklists.json?country_id=`, кеш сбрасывается при смене государства.
  Условия считаются валидатором по сюзерену чек-листа (`ChecklistValidator.new(sovereign)`);
  для этого `Country#show_current_trade_level` принимает государство-партнёра
  (`show_current_trade_level(partner = Country.current)`) — без этого условия типа
  `trade_turnover` падали с 500 («wrong number of arguments (given 1, expected 0)») и блок
  чек-листов не открывался вовсе. Регресс закрыт тестами.
  условия/проценты/отношения считаются по сюзерену; установка и снятие вассалитета действуют
  для пары «текущее государство ↔ вассал» (флаги хранятся по паре, ТЗ № 1, Д14.1).
* 7.2 Доход от вассалов: получает Казначей текущего государства, сумма видна в разбивке дохода;
  суммы вассальных доходов редактируются по сюзеренам —
  `GET /game_parameters/get_vassalage_settings.json?country_id=`,
  `PATCH /game_parameters/update_vassalage_settings.json?country_id=` (хранится полная карта
  `by_sovereign`, правка одной команды не стирает чужие настройки).
* 7.3 Прочие экраны движка (`CaravanRobbery`, `Screen`, `ScreenManagement`, `TradeTurnoverScreen`,
  `PoliticalAction`, `NobleHelper`, `Settings`) — списки целей/стран/регионов строятся по
  текущему государству.
* 7.4 «Артель» (`ACTIVE_GAME=artel`): `ArtelScreen.vue` и экономические экраны артели —
  по текущему государству. Мобильные экраны движка — вне объёма.

## 8. Расходы государства

Одна кнопка в шапке на всю игру → подтверждение расходов **по каждому государству**:

* флаг хранится по государству и году (у аудитов `Country` — `params.state_expenses` хэшем
  по годам, прежние аудиты `GameParameter` — скалярный флаг на игру, читаются для истории);
* `PATCH /game_parameters/pay_state_expenses.json?country_id=` /
  `unpay_state_expenses.json?country_id=`; подтверждение одного государства не подтверждает
  и не отменяет расходы другого;
* в шапке рядом с кнопкой — год и название государства, состояние («оплачено / не оплачено»)
  пересчитывается при смене государства;
* при смене года у неподтвердившего государства «Не оплачены расходы» появляется в общественном
  порядке его регионов и его Казначей не получает бонус влияния; у подтвердившего — появляется
  бонус; формулировки в уведомлениях — с годом и названием государства
  (`src/layouts/components/Notifications.vue`);
* раздел «Госрасходы» в «Статистике» (`DetailedYearlyStats.vue`, `YearlyStats.vue`) группируется
  по государствам (кто подтвердил, кто нет, за какой год).

## 9. Годовые результаты по государству и году

* Знать — ранжирование по влиянию **в текущем государстве**; купцы — гильдии текущего
  государства (капитал = деньги гильдии + стоимость её предприятий).
* Экраны результатов показывают текущее государство; в «Статистике» добавлен раздел
  «Результаты государств» (`src/views/pages/general/ResultsSummary.vue`) — сводка по всем
  командам «только чтение».
* Подэкран и настройки показа (`screen_bundle`, `get/update_merchant_results_settings`,
  `change_results_display`) — на государство: выбор одной команды не меняет экран другой.
* Год: текущий год — живым расчётом (`source: "live"`), прошедшие — снимком; в интерфейсе
  переключатель года с подписью «Итоги года N»; в API отдаётся признак источника.
