Общее правило для всех пунктов: **отдельного «режима на несколько команд» нет**. Приложение всегда работает в разрезе текущего государства (ТЗ № 1, § 4). Если играбельное государство одно, оно и есть текущее: мастер ничего не выбирает, экраны выглядят и работают как прежде. Если играбельных государств несколько, появляется выбор государства и данные разделяются по государствам — без каких-либо переключателей режима.

Отсюда правило приёмки: каждый пункт проверяется в двух конфигурациях — (1) играбельное государство одно, поведение обязано совпасть с текущим; (2) играбельных государств несколько, данные обязаны быть разделены корректно.

## 1. Сквозные изменения

### 1.1. Выбор текущего государства (требование «Информация», п. 0)

Целевое поведение:

- В шапке интерфейса рядом с выбором мастера (`era_front/src/layouts/components/UserProfile.vue`) появляется выбор государства: иконка/бейдж с флагом и названием текущего государства, выбор сохраняется в сессию (`GET /login_country/:id.json`).
- Список для выбора — играбельные государства (`GET /countries.json?playable=1`). Если такое государство одно, бейдж просто показывает его без выпадающего списка (менять не на что) — это и есть «играю за одну страну, всё как прежде».
- Выбор доступен из любого раздела; после смены государства содержимое экранов перечитывается (сброс кэшей компонентов и повторная загрузка данных).
- Бейдж виден всегда, чтобы мастер знал, «за кого» он сейчас работает.

Бэкенд:

- `session[:country_id]`, `ApplicationController#set_current_country`, `Country.current` (ТЗ № 1, § 4, Д1);
- `GET /current_country.json` — текущее государство сессии;
- `GET /login_country/:id.json` — установить текущее государство (валидация: страна существует и `playable`; иначе 422 и сессия не меняется).

Фронт:

- новый компонент `era_front/src/layouts/components/CountryProfile.vue` (по образцу `UserProfile.vue`);
- подключение в шапке интерфейса;
- переиспользуемый composable `era_front/src/composables/useCurrentCountry.js`: `currentCountry`, `playableCountries`, `loadCurrentCountry()`, `setCurrentCountry(id)`, `reloadAll()`.

Критерии приёмки:

- [ ] Выбор есть в шапке, доступен на всех экранах, состояние сохраняется между перезагрузками страницы (сессия).
- [ ] После смены государства все разделы показывают данные нового государства (проверяется на всех разделах из п. 2–6).
- [ ] При единственном играбельном государстве выбора нет — бейдж показывает его, данные как прежде.
- [ ] Прямой API-вызов `GET /login_country/999.json` не ломает сессию.

### 1.2. Перевод Русь-центричных мест на текущее государство (бэкенд)

Полный список — приложение А ТЗ № 1. На этом этапе правится каждое место: `Country::RUS` → `Country.current`, `Job.find_by_id(Job::X).players` → `Country.current.council_players(Job::X)` (ТЗ № 1, § 8.3), `Technology.is_open` → `is_open(Country.current)`, регионы/поселения → скоупы `for_country`.

Отдельно:

- `GameParameter#increase_year` (`app/models/game_parameter.rb:1059-1102`): бонус Казначея и сброс `income_taken` — по каждому играбельному государству (у каждой команды свой Казначей);
- расходы государства: `GameParameter.pay_state_expenses` / `unpay_state_expenses` (`:1108-1123`) и аудит — по каждому государству (ТЗ № 1, Д12; раздел 8 этого ТЗ);
- годовые результаты: `GameParameter.show_noble_results` / `show_sorted_results` / `screen_bundle` (`:324-575`) — в разрезе государства и года (ТЗ № 1, Д13; раздел 9 этого ТЗ);
- движки: `engines/vassals_and_robbers/**` (чек-листы, валидатор, союзы, доход вассалов, доступные места строительства) и `engines/artel/**` (технологии, ресурсы, предприятия гильдий) — по текущему государству (ТЗ № 1, Д14 и § 15; раздел 7 этого ТЗ).
- `PublicOrderItem.add(...)` без региона (`app/models/public_order_item.rb:17`) — на регионы текущего государства.
- `Region#captured_by` (`app/models/region.rb:42`) — бонус «за присоединение» получает совет государства-получателя.

Критерии приёмки:

- [ ] В `app/`, `lib/` не осталось обращений к `Country::RUS` в логике (кроме самой константы и обратной совместимости вида `|| Country::RUS`).
- [ ] При одном играбельном государстве поведение идентично текущему (регресс-прогон по разделу 10).

### 1.3. Игроки привязаны к государству (требование «Информация», п. 2)

- Карточка игрока (`era_front/src/pages/players.vue`) получает поле «Государство»: селект стран (`GET /countries.json`), в форме создания и редактирования (`:244-265`, `:420-459`). Поле есть всегда; при единственном играбельном государстве оно предзаполнено им.
- Список игроков: колонка «Государство», фильтр по государству (дополнительно к существующим фильтрам по типу и семье, `:340-370`).
- `POST/PATCH /players.json` принимает `country_id` (`app/controllers/players_controller.rb:172` — добавить в `permit`).

Критерии приёмки:

- [ ] Новый игрок создаётся с выбранным государством; смена государства у игрока отражается в совете, доходе и армиях.
- [ ] `GET /players.json?country_id=X` возвращает только игроков государства X.
- [ ] Массово создаваемые/сидируемые игроки получают государство по умолчанию (текущее), а не пустое значение.

### 1.4. Влияние и доход привязаны к игроку (требования «Информация», п. 4 и 7)

Схема не меняется (ТЗ № 1, Д6). Функционально:

- Таблица «Знать» (`era_front/src/views/dashboard/Nobles.vue`) — строки это игроки (не должности); колонка «Должности» остаётся информационной; правки влияния и дохода (`add_influence`, `add_income`, удаление `influence_items`/`income_items`) действуют на игрока. Это поведение сохраняется и после перехода на «свой совет в каждом государстве».
- Проставляется явная проверка: ни один путь начисления влияния не может адресовать должность (влияние всегда `influence_items.player_id`, ТЗ № 1, § 8.6). Покрывается тестом: `PoliticalAction#execute` по каждому действию либо начисляет влияние игроку, либо не начисляет вовсе.
- Кнопка получения дохода (зелёная) — на игроке, флаг `players.params['income_taken']` (без изменений), но доход считается только от владений текущего государства (§ 3.7).

Критерии приёмки:

- [ ] После смены держателя должности влияние и доход остаются у прежнего игрока, а у нового начинаются с нуля (кроме влияния от зданий).
- [ ] В таблице «Знать» отображаются только игроки текущего государства.

## 2. Раздел «Дашборд» (новый)

### 2.1. Навигация и маршрут

- Новый пункт в меню `era_front/src/layouts/components/NavItems.vue` — «Дашборд», иконка `ri-dashboard-2-line`, маршрут `/dashboard` (новый экран `era_front/src/pages/teams-dashboard.vue`).
- Текущий экран `/dashboard` («Информация») переезжает на маршрут `/country` и переименовывается в «Информация о стране» (§ 3). Редирект `/` → `/dashboard` сохраняется (`era_front/src/plugins/router/routes.js:1-40`).
- Раздел доступен всегда; при единственном играбельном государстве в списке стран для чекбоксов будет одна «Русь» и остальные государства как партнёры.

### 2.2. Выбор государств чекбоксами (требование 1)

- В верхней части экрана — блок чекбоксов со списком стран (`GET /countries.json`), по умолчанию отмечено текущее государство.
- Мультивыбор: можно отметить 1..N государств; снятие всех чекбоксов — экран с пустой таблицей и подсказкой «Выберите хотя бы одно государство».
- Выбор сохраняется на клиенте (localStorage, ключ вида `dashboard_countries`) — это «настройка вида», не игровое состояние; при первом заходе подставляется текущее государство.
- Рядом — кнопка «Сбросить» (все страны) и «Только текущее государство».

### 2.3. Таблица отношений (требование 2)

Содержание: отношения выбранных государств со **всеми остальными** государствами. Пары, где **оба** государства выбраны, не показываются (иначе одна и та же пара дублируется с двух сторон).

Правило формирования строк:

```
для каждого A из выбранных:
  для каждого B из всех стран, B != A:
    пропустить, если B тоже выбран
    строка (A, B)
```

Данные: отдельный эндпоинт `GET /countries/relations_matrix.json?country_ids=1,2`. Ответ — матрица значений отношений по каждому из запрошенных государств (использует `Country#relations_with`, ТЗ № 1, Д4). Отдельный эндпоинт предпочтён расширению `countries.json`, который используется ещё в 6 экранах.

Оформление — «в одну таблицу, как и сейчас, со всеми кнопками, как сейчас» (эталон: `era_front/src/views/dashboard/Relations.vue:345-420`). Колонки строки:

| Колонка | Содержимое | Действия (как сейчас) |
|---|---|---|
| Государство A | название + флаг; кнопка-меню со списком правок отношений `relation_items` этой пары | удаление правки (`DELETE /relation_items/:id`), «Добавить ручную правку» (`PATCH /countries/:id/add_relation_item`) |
| Государство B | название + флаг | — |
| Отношения | значение пары (-2..+2) | «+1» / «-1» (`PATCH /countries/:id/add_relation_item` с `partner_country_id`), значок союзов (если `alliances_enabled`) с диалогом `AlliancesDialog`, значок эмбарго, кнопка «улучшить через торговлю» (с торговыми очками пары) |
| Комментарий | пусто или текущий статус (например, эффект блокировки улучшения) | — |

Правки и кнопки действуют **в контексте государства A** (то есть от имени пары A↔B): это то же поведение, что сейчас, где пары фактически были «страна ↔ Русь».

Бэкенд:

- `PATCH /countries/:id/add_relation_item.json` — принимает `partner_country_id` (по умолчанию — текущее государство);
- `RelationItem` отдаётся с `partner_country_id` и `partner_country`;
- `Country#relation_items_with(partner)` для меню правок;
- торговые очки — `Country#relation_points_for(partner)` (ТЗ № 1, Д10); кнопка «улучшить через торговлю» вызывает `PATCH /countries/:id/improve_relations_via_trade.json?partner_country_id=<B>`;
- проверки эффектов (`no_relation_improvement`, `non_negative_relations`) применяются к паре: у эффекта `non_negative_relations` цель — название страны (сейчас `self.name`, `app/models/country.rb:312`), в паре нужно определить, какую из двух стран считать целью — рекомендация: цель = государство A строки (страна, за которую мастерим).

Критерии приёмки:

- [ ] При выборе 3 государств таблица содержит строки «A→остальные», «B→остальные», «C→остальные», без пар между A, B, C и без дублей.
- [ ] Изменение отношений в одной строке сразу отражается в значении пары (в том числе если та же пара видна в другом разрезе).
- [ ] Кнопки работают как раньше: ручная правка, ±1, торговые очки, союз, эмбарго.
- [ ] При единственном играбельном государстве отмеченная «Русь» даёт ту же строку по каждой стране и те же значения, что нынешний блок «Отношения» на экране «Информация».
- [ ] Снятие всех чекбоксов не ломает экран (пустое состояние с подсказкой).

## 3. Раздел «Информация о стране» (переименование + 8 требований)

Переименование: `NavItems.vue` — «Информация» → «Информация о стране»; маршрут `/country`; компоненты `era_front/src/views/dashboard/*` остаются, но получают текущее государство как источник данных.

### 3.1. Смена государства (п. 0)

Смена выполняется в шапке (§ 1.1) и дублируется в заголовке раздела: «Информация о стране: {название}» с кнопкой смены (то же действие). Требование «возможность сменить государство в интерфейсе era_front» выполнено шапкой; заголовок нужен, чтобы мастер видел контекст.

### 3.2. Технологии (п. 1)

- Технологии в каждом государстве одинаковые по номенклатуре, открываются отдельно (ТЗ № 1, Д5).
- Экран: `era_front/src/views/dashboard/Technologies.vue` — загрузка `GET /technologies.json?country_id=<текущее>`, переключатели меняют флаг технологии **этого** государства (`PATCH /technology_items/:id.json`, где `id` — элемент текущего государства).
- В карточке технологии подписано, чей это флаг (название государства), чтобы не спутать при нескольких командах.
- Эффекты технологий не меняются (прямое требование).

Критерии приёмки:

- [ ] Открытие технологии у одного государства не меняет состояние у другого.
- [ ] Смена государства перерисовывает список (`is_open` меняется).
- [ ] При единственном играбельном государстве поведение и вид как сейчас.

### 3.3. Знатный совет (п. 3)

- Таблица «Знать» (`Nobles.vue`) показывает совет текущего государства: игроки `player_type_id = 2` с `country_id = текущее`.
- Должности показываются тем же списком (10 позиций справочника), но заняты игроками этого государства; у незанятой должности — серая плашка «должность не занята».
- Смена держателя должности — из раздела «Политика → Политические действия» (§ 5), в контексте государства.
- Бэкенд: `Country#council_players`, `GET /players.json?country_id=&player_type_id=2`.

### 3.4. Влияние (п. 4)

- Влияние отображается и правится на игроке (`Nobles.vue`, колонка «Влияние», меню правок).
- Источниками влияния остаются здания (`Player#influence_buildings` — строения в регионах текущего государства) и `influence_items` (в т.ч. от политдействий).
- Проверка: влияние не хранится и не начисляется «на должность» ни в одном сценарии.

### 3.5. Отношения (п. 5)

- Блок «Отношения» (`Relations.vue`) в этом разделе показывает отношения **текущего государства** со всеми остальными: строки — все страны, кроме текущего, значение — `Country#relations_with(текущее, строка)`, кнопки те же.
- Данные: `GET /countries.json?foreign=1` («всё, кроме текущего», ТЗ № 1, § 9) + `relations_by_country` из ответа.
- Дашборд (§ 2) и этот блок используют один и тот же компонент строки/таблицы — выносится в общий компонент (`era_front/src/components/RelationsRow.vue` или параметризованный `Relations.vue` с пропом `pairs`), чтобы «все кнопки, как сейчас» не поддерживать в двух копиях.

Критерии приёмки:

- [ ] В списке нет самого текущего государства.
- [ ] Правки отношений, ±1, торговые очки, союз, эмбарго работают так же, как в Дашборде.
- [ ] Значения совпадают с матрицей Дашборда для той же пары.

### 3.6. Доходы (п. 6)

- Доход игрока считается только от владений, расположенных в регионах текущего государства (`Player#income_breakdown(country)`, `GET /players/:id/income_breakdown.json?country_id=`).
- В разбивке видны поселения игрока этой страны; поселения игрока в других странах в этот блок не попадают.
- Надбавки: «Торговая надбавка» и «Доход от церквей» считаются по должностям совета текущего государства и по церквям в его регионах (`app/models/player.rb:296-318, 355-372` — заменить `Country::RUS`).
- Итоговая сумма `players.json` (`Player#income`) тоже зависит от текущего государства — фронт не суммирует сам.

### 3.7. Получение дохода (п. 7)

- Кнопка на цифре дохода остаётся на игроке и сохраняет цвет (`success` = доход получен, `error` = нет) и поведение `PATCH /players/:id.json {params: {income_taken: ...}}` (`era_front/src/views/dashboard/Nobles.vue:124-131, 235-243`).
- Дополнительно: подпись о государстве, к которому относился полученный доход (аудит год/сумма уже пишется, `app/models/player.rb:486-503`), чтобы отчётность не смешивалась между командами.
- Сброс флага при смене года остаётся как сейчас, но применяется ко всем играбельным государствам (ТЗ № 1, § 1.2 — `increase_year`).

Критерии приёмки:

- [ ] Цифра дохода и кнопка меняются при смене государства (доход считается по владениям текущего государства).
- [ ] Смена держателя должности не влияет на флаг и сумму дохода игрока.
- [ ] При единственном играбельном государстве значения совпадают с текущими (сверка на боевой копии базы).

## 5. Раздел «Политика → Политические действия»

Требования:

1. Набор действий тот же; эффекты действий не меняются.
2. Факт выполнения отмечается для каждой страны отдельно: проверка «выполнено» — по `(job, year, country_id)` (`political_actions.country_id`, ТЗ № 1, Д9).

Критерии приёмки:

- [ ] Отметка «выполнено» у «Руси» не влияет на отметку той же должности другого государства и наоборот.
- [ ] Смена Великого князя в одном государстве не меняет держателей этой должности в других государствах (проверяется на двух государствах).
- [ ] Список должностей и держатели соответствуют текущему государству; после смены государства список перерисовывается.
- [ ] При единственном играбельном государстве экран идентичен текущему.

Данные — `GET /armies.json` (все армии), владельцы — `countries.json?foreign=1` + знать.

## 7. Движки: вассалитет (`vassals_and_robbers`) и «Артель» (`artel`)

Общее: механики движков работают в разрезе текущего государства. При одном играбельном государстве («Русь») всё выглядит и работает как прежде. Бэкенд-часть — ТЗ № 1, Д14 и § 15.

### 7.1. Вассалитет и чек-листы

- Блок «Чек-листы» (`era_front/src/views/dashboard/Checklists.vue`, композабл `src/composables/useChecklists.js`) загружает `GET /vassals_and_robbers/checklists.json?country_id=<текущее>` — чек-листы, у которых сюзерен = текущее государство. Кеш композабла сбрасывается при смене государства.
- Карточка `src/views/pages/aux/ChecklistCard.vue`: условия, проценты выполнения и отношения — в разрезе сюзерена; кнопки «Установить вассалитет» / «Снять вассалитет» (`POST /vassals_and_robbers/checklists/:id/establish_vassalage.json` / `remove_vassalage.json`) действуют для пары «текущее государство ↔ вассал».
- Установка вассалитета одним государством не меняет данные другого: флаги хранятся по паре (ТЗ № 1, Д14.1).
- Блок доступен для любого играбельного государства; если у государства нет вассальных стран — пустое состояние «Нет доступных вассалов».

### 7.2. Доход от вассалов

- Доход от вассалов получает Казначей **текущего** государства и он входит в доход по должности на экране «Информация о стране → Знать» (раздел 3.6).
- В «Служебное → Настройки» (`src/views/pages/aux/Settings.vue`) суммы вассальных доходов редактируются по каждому сюзерену (`GET/PATCH вассальных настроек`), а не одним общим списком.

### 7.3. Прочие экраны движка

- `src/views/pages/aux/CaravanRobbery.vue` (разбой караванов), `Screen.vue`, `ScreenManagement.vue`, `TradeTurnoverScreen.vue`, `PoliticalAction.vue` (движковые политдействия), `NobleHelper.vue` — выбор целей, стран и регионов в контексте текущего государства (списки строятся по текущему государству, а не по «Руси»).
- Экран «Политические действия»: действия, добавленные движком, отмечаются по (должность, год, государство) — как в разделе 5.

### 7.4. «Артель» (`ACTIVE_GAME=artel`)

- `src/views/pages/aux/ArtelScreen.vue` и экономические экраны артели (предприятия принадлежат гильдии, ресурсы без привязки к региону) работают для текущего государства: гильдия владеет предприятиями своего государства, цены и караваны — по текущему государству (бэкенд — ТЗ № 1, Д14.2).
- При одном играбельном государстве экран и суммы совпадают с текущими.
- Мобильные экраны движка (`src/views/pages/politics/ChecklistsMobile.vue` и прочие) — вне объёма (как и остальные мобильные экраны).

Критерии приёмки:

- [ ] Чек-листы вассалитета у каждого государства свои: установка вассалитета в одном не видна в другом, снятие не затрагивает чужой чек-лист.
- [ ] Доход от вассалов попадает Казначею текущего государства и меняется при смене государства.
- [ ] Условия чек-листа считаются по сюзерену (армии, отношения, союз, технологии, товарооборот, предприятия, общественный порядок).
- [ ] Экран «Артель» работает для текущего государства; при одном играбельном государстве значения совпадают с текущими.

## 8. Расходы государства: подтверждение по каждому государству

Текущее состояние: одна кнопка в шапке на всю игру (`era_front/src/layouts/components/DefaultLayoutWithVerticalNav.vue:20-70` → `PATCH /game_parameters/pay_state_expenses.json` / `unpay_state_expenses.json`), флаг — `GameParameter('current_year').params['state_expenses']`, уведомления об оплате/отмене — `src/layouts/components/Notifications.vue:575-590`.

Требования:

1. Кнопка подтверждения расходов действует для **текущего** государства; рядом подписан год и название государства.
2. Индикация состояния «оплачено / не оплачено» — по текущему государству; после смены государства кнопка и цвет сразу отражают его состояние.
3. Смена года: у каждого государства, не подтвердившего расходы, «Не оплачены расходы» появляется в общественном порядке **его** регионов и его Казначей не получает бонус влияния; у подтвердившего — появляется бонус. Формулировки в интерфейсе — с названием государства.

Критерии приёмки:

- [ ] На двух играбельных государствах: подтверждение расходов у первого не подтверждает их у второго (и наоборот отмена).
- [ ] После смены года у неподтвердившего государства «Не оплачены расходы» стоит в его регионах, бонус Казначею не начислен; у подтвердившего — начислен.
- [ ] В «Статистике» видна разбивка по государствам за каждый год игры.
- [ ] При одном играбельном государстве поведение, вид кнопки, уведомления и суммы совпадают с текущими.

## 10. «Служебное»: состав играбельных государств

## 13. Тест-план этапа 2 и критерии готовности

Стенды: (1) `rake game:teams` — играбельное государство одно («Русь»); (2) `TEAMS="Русь,Литва" rake game:teams` — играбельных государств несколько.

Сценарии для каждого стенда (все обязательны):

1. Текущее государство из шапки на каждом разделе → данные соответствуют этому государству (список игроков, совет, технологии, отношения, владения, армии, политдействия). На стенде 1 — совпадают с прежним поведением.
2. Дашборд: одна страна, две страны, все страны; проверка отсутствия пар «друг с другом» и отсутствия дублей.
3. Отношения: +1/-1, ручная правка (добавить/удалить), торговые очки (начислить торговлей и потратить), союз, эмбарго — по паре государств.
4. Технологии: открытие у одного государства не меняет у другого; возврат к первому показывает прежнее состояние.
5. Политдействия: отметка выполнения по государству; смена держателя должности в одном государстве не затрагивает другие.
6. Армии: состав вкладок, создание армии (знать/государство), атака между армиями разных государств.
7. Доход: сумма и разбивка соответствуют владениям текущего государства; кнопка получения дохода на игроке; сброс флага на новом году.
8. Влияние: правка на игроке; после смены держателя должности влияние остаётся у игрока.
9. Расходы государства: подтверждение у одного государства и отмена у другого; смена года → у неподтвердившего «Не оплачены расходы» в его регионах, у подтвердившего бонус Казначею; разбивка в «Статистике» по государствам.
10. Годовые результаты: таблицы знати и купцов по текущему государству; свой подэкран и настройки у каждого государства; переключение года (снимок прошлого года не меняется после смены года).
11. Движки: чек-листы вассалитета по текущему государству (условия, проценты, установка/снятие), доход от вассалов у Казначея государства, доступные места строительства = государство + его вассалы, экран «Артель» для текущего государства.

Регресс «игра за одну страну» (обязательный, отдельным прогоном на стенде 1):

- Скриншоты каждого раздела до и после доработки: различия допустимы только в добавленных элементах (бейдж текущего государства, чекбоксы Дашборда, новые поля).
- API-паритет по списку из ТЗ № 1, § 12 п. 3.
- Проверка, что нигде в интерфейсе не появилось переключателей/режимов и признаков «одна команда / много команд».

Критерии готовности этапа 2:

- [ ] Все требования разделов «Дашборд», «Информация», «Политика» (Владения, Политические действия), «Сражения» выполнены и проверены на стенде с несколькими государствами.
- [ ] На стенде с одним играбельным государством каждый пункт требований не изменил прежнее поведение.
- [ ] Эффекты технологий и политических действий не изменены (явное требование).
- [ ] Расходы государства подтверждаются по каждому государству, годовые результаты считаются по каждому государству (разделы 8–9).
- [ ] Движки `vassals_and_robbers` и `artel` работают в разрезе текущего государства (раздел 7).
- [ ] Ошибок в консоли браузера и 5xx в логах бэкенда при сценариях нет.
- [ ] Документация: обновлены `README_DEV_STARTUP.md` (запуск с `TEAMS`) и заметки в `docs/many_teams/`.

## 14. Риски этапа 2

| Риск | Оценка | Что делаем |
|---|---|---|
| Двойной источник «страны» на фронте (текущее государство в шапке и параметры запросов) → рассинхрон | Высокий | Единый composable `useCurrentCountry.js`; запросы строятся через него; после смены государства — принудительное перечитывание данных на активном экране |
| Полная замена держателей должности при `PATCH /jobs/:id` стирает чужой совет | Высокий | § 5 п. 4 — формирование списка «держатели других государств + выбранный игрок»; покрыть тестом на двух государствах |
| Таблица «как сейчас со всеми кнопками» дублируется в Дашборде и «Информации» | Средний | Общий компонент строки отношений (§ 3.5) |
| База, забэкфилленная из прежней версии, при добавлении второго государства потребует разбора пар и торговых очков | Средний | Бэкфилл из ТЗ № 1, § 11 (парные очки в ключ «Руси» и отчёт по самопарам) + предупреждение в блоке «Играбельные государства» |
| Движки не поддерживают игру за несколько государств (чек-листы вассалитета, плагин artel) | Средний | Блок скрывается вне «Руси» с пояснением; полноценная поддержка — отдельный этап |
| Забытые Русь-центричные места в редких сценариях (пленение, аренда армий, разбой караванов) | Средний | Прогон по инвентарю приложения А ТЗ № 1 + тесты на места, где влияние/доход выдаются от должности |
| Расходы государства: переезд аудита с `GameParameter` на `Country` рвёт историческую статистику | Средний | Читать оба источника аудита; в отчёте указывать государство и год |
| Снимки годовых результатов могут разойтись с живым расчётом после смены года | Средний | Снимок делается до смены года, идемпотентен, в API отдаётся признак источника (`live` / `snapshot`) |
| Движки правятся в той же ветке, что и ядро: миграция сюзерена чек-листов может не накатиться с общей задачей | Средний | Миграция движка проверяется в общем `db:migrate`; сюзерен nullable + бэкфилл «Русь» |
| Экран «Артель» (`ACTIVE_GAME=artel`) легко забыть при проверках | Средний | Отдельный прогон тест-плана в режиме артели (раздел 7.4) |
